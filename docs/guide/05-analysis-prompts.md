# Промпты анализа

> Последняя сверка: 2026-11-09

## Что и зачем

Менять, **что** AI проверяет в сделке, лиде или смарт-процессе, можно без
нового выпуска модуля. Для этого у анализа есть **механизм шаблонов
промпта**: стандартный текст в коде, свой — в разделе «Промпты анализа»
настроек модуля, с переменными, версией и предпросмотром.

## Где править

Страница модуля, раздел «Промпты анализа»
(`/shef/toolsaicrm/?section=prompts`, [Страница модуля](09-public-settings.md)).
Правят администратор и сотрудник с действием «Промпты: править» в ролях
shef.toolsai; без него раздел открыт только для чтения.

Правится только текст задания. Форму ответа и правила JSON модуль
дописывает сам. Шаблоны лежат в таблице `shef_toolsaicrm_prompt`, коды `analysis.…`.
Промпты остальных функций AI (звонки, чаты, помощник) — в shef.toolsai.

## Уровни

Свой шаблон можно задать на нескольких уровнях. Зачем: у направления
«Опт» и направления «Розница» разные признаки риска, а у каждого
смарт-процесса — своя работа.

| Уровень | Код (`PromptLevel::code()`) |
|---|---|
| сделки, общий | `deal` |
| сделки, направление N | `deal.cN` |
| лиды | `lead` |
| смарт-процесс X, общий | `dynamic.X` |
| смарт-процесс X, воронка N | `dynamic.X.cN` |

Действует **ближайший свой** по цепочке: воронка -> тип -> стандартный
шаблон модуля (`Analysis\Prompt\PromptResolver`). Воронка — та, по
которой подбирается профиль записи; у лида и смарт-процесса без воронок
уровня воронки нет.

На странице сверху — выбор уровня (у уровней со своим шаблоном пометка
«— свой»). Под ним видно, какой шаблон на уровне реально действует:

* **свой** — версия, кто и когда менял;
* **унаследован** от уровня «…» — своего нет, работает шаблон выше;
* **стандартный** — своих нет ни на уровне, ни выше.

Сохранение создаёт свой шаблон выбранного уровня. **«Вернуть
стандартный»** удаляет свой шаблон уровня — дальше уровень наследует
шаблон выше (или стандартный); на кнопке написано, какой именно.

## Что на странице

* **Инструкция модели** — системная часть;
* **Данные** — что модель получает как данные; по умолчанию
  `{сводка}` и `{история}`;
* **Свои поля ответа** — до 5 имён латиницей (`mood, deadline`). Модель получает их
  в схеме ответа строками, но модуль проверяет только основные поля: число или
  пропуск в своём поле ответ не роняет — в «AI: история» попадает то, что пришло;
* «Сохранить» — версия +1, запоминается кто и когда;
* «Удалить свой шаблон» — с подтверждением; свой текст уровня и его
  свои поля ответа удаляются, работает шаблон уровня выше или стандартный.
  Отдельной кнопки «вернуть стандартный» нет: это то же действие,
  подсказка рядом с кнопкой так и говорит. Убрать одно своё поле ответа —
  стереть его в строке «Свои поля ответа» и сохранить;
* **Предпросмотр** — ID записи типа выбранного уровня: модуль соберёт
  промпт как агент (профиль, сводка, история, шаблон по воронке записи) и
  покажет, **какой уровень сработал**. В модель не уходит, расхода нет.

### Инструкция модели

Системная часть промпта: что модель должна сделать и как оценивать.
Форму ответа (JSON) модуль добавляет сам.

### Свои поля ответа

До 5 имён латиницей через запятую (`mood, deadline`). Модель получает их
в схеме ответа строками. Модуль проверяет только основные поля: число или
пропуск в своём поле ответ не роняет. В «AI: история» попадает то, что
пришло.

### Предпросмотр

Введите ID записи того типа, что у выбранного уровня. Модуль соберёт
промпт как агент и покажет, какой уровень сработал. В модель ничего не
уходит, расхода нет.

## Переменные

| Переменная | Что подставляется |
|---|---|
| `{сводка}` | сводка о записи: стадия, сумма, счётчики и история касаний по времени |
| `{история}` | последние 3 анализа и были ли отметки ([История риска](04-risk-history.md)) |
| `{шкала}` | шкала профиля: с какого риска «низкий», с какого «высокий» |
| `{профиль}` | название профиля |
| `{сущность}` | «сделка», «лид», «элемент «…»» |
| `{лента}` | только история касаний по времени, без карточки и счётчиков ([Анализ сделок](01-deal-analysis.md#история-записи)). Уже входит в `{сводка}`: ставьте её отдельно, если строите свою подачу данных |

Неизвестная `{…}` остаётся как есть. Нет `{сводка}` в «Данных» — модуль
всё равно допишет сводку в конец: без данных модель не работает.

## Что нельзя сломать промптом

* **Форма ответа общая**: `risk`, `needSenior`, `why`, `nextStep` (синоним
  `todo`). Схема уходит модели отдельно (`HealthAnalyzer::schema()`), а к
  своему тексту модуль сам дописывает требование JSON
  (`HealthAnalyzer::JSON_RULE`). Разбор ответа — общий (`Deal\Verdict`).
* **Свои поля** добавляются в схему строками. Их значения сохраняются в
  истории (`EXTRA`) и показываются; на шкалу, дела и эскалацию не влияют.
* **Данные подставляет модуль**, не автор шаблона.

## Что главнее

1. Свой промпт **профиля** (поле «Промпт» в профиле анализа) — заменяет
   системную часть. Переменные в нём тоже работают.
2. Иначе — шаблон по уровням: воронка -> тип -> стандартный.
