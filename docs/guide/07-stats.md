# Статистика

> Последняя сверка: 2026-11-09

## Что и зачем

Два отчёта о том, что автоанализ CRM сделал за период: сколько записей
проверено и как оценена работа менеджеров. Один отчёт — одна страница
модуля со своим пунктом в меню слева и своим адресом:

| Отчёт | Адрес `?section=` | Кто видит |
|---|---|---|
| Анализ записей CRM | `stats_checks` | действие «Отчёты: смотреть» ролей shef.toolsai |
| Оценка работы менеджеров | `stats_managers` | действие «Статистика по всему порталу» ролей shef.toolsai |

Страница считает только свой отчёт — запросы другого отчёта не идут.
Период — один фильтр на оба отчёта: выбранный на одной странице действует и
на другой. Разделы только читают базу (`settings/stats.php`,
[Страница модуля](09-public-settings.md)).

Оценка работы менеджеров доступна и AI-помощнику — инструмент MCP
`toolsai_manager_scores`, с тем же правом ([события и REST для модулей](../dev/rest.md)).

## Период

Период задаётся штатным фильтром Битрикс24 в верхней панели:
свои пресеты, «Сбросить», фильтр запоминается у
пользователя. Ссылка с `?from=&to=` выставляет фильтр сама.

«С» и «по» включительно; по умолчанию — с первого числа текущего месяца по
сегодня. Параметры `from`, `to` — строго `ГГГГ-ММ-ДД`; мусор или
несуществующий день — умолчание; «с» позже «по» — меняются местами
(`Stats\Period::fromRequest()`). Каждая цифра
берёт **своё** поле даты — оно указано в таблицах ниже.

## Анализ записей

Из таблицы проверок `shef_toolsaicrm_entity_check` — сделки и лиды всегда, элементы
смарт-процессов — с профилем анализа или с проверками. Одна строка на запись —
**последняя** проверка; запись, проверенная в периоде и ещё раз после него,
в периоде не видна:

| Цифра | Как считается |
|---|---|
| проверено | строк с `CHECKED_AT` в периоде |
| разобрано моделью | из них `SKIPPED = 'N'` |
| пропущено | `SKIPPED = 'Y'` (без модели или с ошибкой) |
| дел менеджерам | `MANAGER_TODO_AT` в периоде |
| к старшему | `ESCALATED_AT` в периоде |
| о просрочке старшему | `OVERDUE_NOTIFIED_AT` в периоде (нет столбца — цифры нет) |

Комментарий «Старшего не привлекаем» (`NOTE_COMMENTED_AT`) и
строку `ACTION` статистика не считает — они видны в последних проверках агента
([Общий блок анализа](02-analysis-block.md#последние-проверки-агента)).

### По типу записи, ответственному и профилю

Группировка по `ENTITY_TYPE_ID` проверки (сделки, лиды, смарт-процесс «…»),
по ответственному записи (`ASSIGNED_BY_ID` её таблицы — `b_crm_deal`,
`b_crm_lead`, таблица элементов смарт-процесса; `Stats\AnalysisOwners`) и по
`PROFILE_ID` проверки: записей проверено, **средний риск** (только разобранные моделью, округление
до целого), дел менеджеру, к старшему.

## Оценка работы менеджеров

Анализ записи оценивает и работу ответственного — по звонкам,
письмам и чатам (`managerScore`, [Анализ сделок](01-deal-analysis.md),
«Ответ модели»). Блок берёт её из истории анализа сделок,
лидов и смарт-процессов (`shef_toolsaicrm_analysis_history`, `EXTRA`) за период по `CREATED_AT`, по ответственному записи
**сейчас** (`ASSIGNED_BY_ID` её таблицы, `Stats\AnalysisOwners`), до 20 000
строк: анализов с оценкой, средняя и худшая (в %); худшие первыми
(`Stats\ManagerScores`). Оценка -1 («оценивать нечего») не считается.

## Имена

Сотрудник — «Фамилия Имя», нет — логин, нет — `#ID`.

## Средние и проценты

* средние — `AVG` в базе, округление до целого; нет данных — «—»;
* доля — от оценённых, не от всех.
