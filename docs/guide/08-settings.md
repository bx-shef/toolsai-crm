# Настройки

> Последняя сверка: 2026-11-09

## Что и зачем

Настройки автоанализа CRM — на странице модуля в публичной части портала:
`/shef/toolsaicrm/` (слайдер), раздел «Общие» (`?section=options`). Профили,
промпты и отчёты — свои разделы там же ([Страница модуля](09-public-settings.md)).
Те же общие настройки — на странице модуля в «Настройки → Настройки модулей», вкладка «Автоанализ CRM».
Кнопки «Вернуть значения по умолчанию» нет: поле, которое нужно вернуть, правят руками.

У каждой настройки значок «?» — что это и зачем (ответ — в статье «Вопросы и
ответы» «Базы знаний», тексты — `settings/faqdata.php`).

Код настройки = префикс блока + имя (`options_conf.php`). Умолчания —
`default_option.php` и константы `Config`. Значение вне границ или мусор —
берётся умолчание (`Main\OptionParser`).

Подключение модели, ключи, расход, месячная квота, лицензия и права доступа —
**в настройках shef.toolsai**: модуль берёт их оттуда ([Лицензия, квота и расход](10-quota.md)).
В «Общих» на эти разделы стоят ссылки.

## Блок «Анализ сделок» (DEAL)

| Код | Смысл | Умолчание |
|---|---|---|
| `DEAL_enabled` | включить агенты анализа | N |
| `DEAL_maxperrun` | анализов моделью за прогон, 1–500; общее значение для агентов типов | 50 |
| `DEAL_interval` | раз в N минут, 10–10 080; общее значение для агентов типов; применяется сразу после сохранения | 60 |
| `DEAL_crmevents` | запускать события Битрикс24, роботы и бизнес-процессы при записи модуля в CRM ([Анализ сделок](01-deal-analysis.md#запись-в-crm-роботы-и-бизнес-процессы)) | N |

Всё остальное — направления, типы клиента, промпты, границы риска, старшие,
сроки, «Тотальный контроль» — в профилях ([Анализ сделок](01-deal-analysis.md)).
Название блока в коде — «DEAL»: под этим именем хранятся коды настроек.

**«Тотальный контроль»** — флажок в форме профиля, столбец `TOTAL_CONTROL`
таблицы `shef_toolsaicrm_deal_profile`, по умолчанию `N`. Включён — при риске от
`HIGH_BORDER` старший получает дело всегда, даже если модель считает его
ненужным. Дел старшему может стать много — тогда флажок выключают.

**Агенты анализа.** У каждого типа свой интервал и лимит — раздел
«Авто-анализ CRM», блок «Агенты анализа»: настройки `ANALYSIS_interval_{тип}`
(минуты, 10–10 080) и `ANALYSIS_maxperrun_{тип}` (1–500). Пусто — общие
`DEAL_interval` и `DEAL_maxperrun` (`Config::getAnalysisInterval()`,
`Config::getAnalysisMaxPerRun()`).

## Скрипты оценки звонков (CALLSCRIPT)

| Код | Смысл | Умолчание |
|---|---|---|
| `CALLSCRIPT_mode` | `core` — скрипт выбирает Битрикс24; `rules` — по правилам модуля | `core` |
| `CALLSCRIPT_fallback` | запасной скрипт, когда правило не подошло | пусто |

Правила хранятся в таблице `shef_toolsaicrm_call_script_rule`; подробно —
[Анализ сделок](01-deal-analysis.md#скрипты-оценки-звонков). Раздел «Авто-анализ CRM».

## Что не меняется

Коды настроек (`DEAL_*`, `ANALYSIS_*`, `CALLSCRIPT_*`), коды полей
(`UF_SHEF_AI_*`), тип поля `shef_toolsai_ack` и робот БП
(`/bitrix/activities/custom/shtoolsaianalyzeactivity`, класс
`CBPShToolsAiAnalyzeActivity`) — фиксированы: на них лежат
данные порталов и схемы бизнес-процессов. Значения настроек при установке
переносятся из shef.toolsai ([Перенос из shef.toolsai](11-migration.md)).

## Чужие настройки, которые модуль не трогает

Настройки подключения модели, расхода, квоты, лицензии, ролей доступа и
звонков (`crm::ai_integration_*`) — в shef.toolsai; модуль shef.toolsaicrm их
не читает и не пишет, а обращается к движку через его публичный API
(`LlmService`, `AccessService`).
