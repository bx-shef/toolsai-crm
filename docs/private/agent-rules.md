# Правила работы агента

> Последняя сверка: 2026-11-09

Правила — общие для линейки и живут в
[shef.toolsai: docs/private/agent-rules.md](https://github.com/bx-shef/toolsai/blob/main/docs/private/agent-rules.md).
Там прав текст, здесь — выжимка и то, что отличается.

1. **Источник правды по ядру** — код ядра портала и документация Битрикса, не
   память. Опора на ядро — с `файл:строка`.
2. **В `main` — только через PR**, мерж — сквош после зелёного CI и ревью по уровню PR (п. 3).
3. **Ревью** — по уровню PR (по путям изменённых файлов; уровень 0 — без ревью):
   раздел [«Ревью PR»](#ревью-pr) ниже, навык `review-panel`.
4. **Документация — в том же PR**, что и код: `docs/guide`, `CLAUDE.md`,
   `README.md`, `CHANGELOG.md`.
5. **Дисциплина**: замер вместо «должно»; тест краснеет при поломке; никогда
   `git checkout --` для отката чужого.
6. **Решает владелец**: релиз, выкладка в портал клиента, всё необратимое.

Отличия этого репозитория:

* модуль зависит от `shef.toolsai` 1.96.0+, но ходит в него только через публичный API
  (`LlmService`, `AccessService`): классов shef.toolsai в `lib/` нет — держит `tests/seam_test.php`;
* коды настроек (`DEAL_*`, `ANALYSIS_*`, `CALLSCRIPT_*`), поля `UF_SHEF_AI_*`, тип поля и робот БП
  не меняются: на них лежат данные порталов и схемы БП;
* перенос данных из `shef.toolsai` — сверка перед отметкой (`SYS_migrated_from_toolsai`,
  `SYS_crm_moved`); правка переноса — уровень 2;
* справка: `docs/guide` → `kb/guide` (`php tools/kb-build.php`), якоря `settings/faqdata.php` сверяет `tests/kb_test.php`.
7. **Выпуск — агент выпуска, одинаково во всех модулях toolsai** (`plan/version-rule.md`, с 02.11). В PR версия модуля не поднимается: запись — в CHANGELOG под «## Не выпущено». Выпуск делает один агент выпуска по команде ведущего: берёт main, переносит «Не выпущено» в «## X.Y.Z — дата», поднимает `VERSION` в `install/version.php` (и `package.json`, где есть), собирает архив (`plan/build-zip.sh`), ставит тег `v<версия>` после проверки на стенде и выкладывает `gh release create` с разделом CHANGELOG. На стенд ставится только архив выпуска из main. Номер — по semver: новые функции — минор, исправления — патч. Тег с такой версией уже есть — не перезаписываем.

## Ревью PR

Объём ревью задаёт **уровень** PR по путям изменённых файлов: `tools/review-tier.sh --action`
(`--explain` — по файлам). Правила репозитория — `tools/review-tier.rules`; сам движок — копия
эталона bx-shef/toolsai, здесь его не правят. Уровень PR — наибольший из уровней его файлов; не
подошло ни одно правило — уровень 1. Порядок действий — навык `review-panel`
([SKILL.md](../../.claude/skills/review-panel/SKILL.md)). Основная проверка — `./build.sh --check`;
она же сверяет правила уровней.

| уровень | что меняется | ревью | примеры |
|---|---|---|---|
| 0 | только документы, лента «Что нового», версии, карта проекта, тесты без кода модуля, `.gitattributes`, стенд без изменения модуля | без ревью: основная проверка | правка главы справки, строка в CHANGELOG, подъём версии, новый тест |
| 1 | мелкое поведение: всё, что не 0 и не 2 | `/code-review medium --max-findings 5`; уровень `max` запрещён | исправление в одном классе, текст интерфейса, новая настройка без денег и прав |
| 2 | деньги, лицензия, безопасность, установщик, сборка, CI, Dockerfile и образы, публичный API, схема таблиц | панель из пяти параллельно; `/code-review` при панели не зовём | расчёт квоты или цены, проверка лицензии, токен и права, установщик, `Dockerfile`, публичный API, новая таблица |

- **Ручной уровень** главнее автоматического: `tools/review-tier.sh --level N` или `REVIEW_TIER=N`; его же
  задаёт слово владельца («уровень 2», «панель», «без ревью») или строка «Уровень ревью: N» в описании PR.
  Вывод показывает оба: «вручную N, по путям M». Легенда уровней — `tools/review-tier.sh --levels`.
- Агент вправе **поднять** уровень сам (сомнение; правка выросла из рассуждения, а не из замера; в тексте
  цена или условия лицензии), **понизить** вправе только владелец: ручной уровень ниже автоматического
  печатает предупреждение. Пути с пометкой «слово владельца» — стоп до слова владельца.
- Панель: все пять ролей (Документация, Инженер, QA, Безопасность, CTO) — Sonnet, среднее усилие;
  максимум усилия — никогда.
- Повтор: после правок перепроверяет только нашедший замечание; полная панель заново — только если
  PR переписан; серия связанных PR — одна панель на общий дифф.
- Находки чинятся в том же PR; отклонённая находка — с доводом и замером, а не молча. Отчёт —
  по-русски, коротко.

### Режим агентов: «экономия» и штатный

**Режим «экономия» (сейчас):** по умолчанию Sonnet, среднее усилие; Opus, высокое — только деньги,
лицензии, безопасность, установщик, сложные падения; максимум усилия — никогда; агентов 6–8 за раз
(больше — спросить владельца); на стенде одна сборка за раз.

**Штатный режим:** Opus, высокое — деньги, лицензии, безопасность, установщик, сложный дизайн;
Sonnet — механика (ветки, тексты, снимки, чек-листы); низкое усилие — неприоритетное.

## Лента «Что нового» (bx-shef/toolsai#332)

PR, который меняет поведение для пользователя, несёт файл `changelog/<ГГГГ-ММ-ДД>-<PR>.md` — формат в [changelog/README.md](../../changelog/README.md). Текст — для руководителя: 1–2 предложения, что умеет продукт и зачем это нужно, в настоящем времени, без имён классов и цен. Технический PR (CI, документация, тесты, навыки) ленты не несёт: в шаблоне PR — «Лента: технический», строка в «Не выпущено» — с пометкой «(лента: нет)». Держит `build.sh --check`.

## Разовые контейнеры проверок

- Любые разовые `docker run` для проверок (Playwright, node, php…) — только через `../stand/tools/pw-run.sh <проект> <задача> [опции docker run] -- <команда>` (bx-shef/toolsai-stand, клон рядом). Образ Playwright — по умолчанию, другой — `PW_IMAGE=node:22`. Прямой `docker run` для проверок не использовать: обёртка задаёт лимиты памяти и CPU, shm 1 ГБ, --init, отключает дампы WSL, даёт имя, метку project и таймаут (PW_TIMEOUT). Не больше двух прогонов одновременно. Пример: `PW_TIMEOUT=900 ../stand/tools/pw-run.sh <репо> check -v D:/tmp/chk:/w -w /w -- bash -c './build.sh --check'`.
