# Карта модуля shef.toolsaicrm

> Последняя сверка: 2026-10-30 — по коду 1.15.4, релизы `gh release list`

## Цель

«Оповещения для сотрудников» отдельным модулем: любой модуль присылает свои
объявления событием, администратор правит их на одной странице, сотрудник
видит каждое один раз.

## Код

* `lib/announce/` — `Announcements` (слияние объявлений модулей и своих), `Collector` (событие `OnAnnouncementsCollect`), `OwnStore` (свой список в `b_option`, под блокировкой), `SeenStore` (отметки «видел»), `Places`/`PlaceCollector` (места показа, событие `OnAnnouncementPlacesCollect`), `Art`/`Media` (картинки окна), `ListView`/`GridView` (админская и публичная страницы), `McpTools` (манифест MCP).
* `lib/controller/` — `Announcement` (форма и действия списка), `Access` (роли), `Banner` (показ окна и отметка).
* `lib/access/` — роли и права (`ui.accessrights.v2`, таблицы ролей), `UserAccess`.
* `lib/integration/` — REST `shef.announce.*` (`rest/service.php`), пункт меню по аватарке (`intranet/bindingmenu.php`), провайдер мест для `ui.entity-selector`.
* `lib/internals/integration/` — показ окна в `OnEpilog`, пункт шестерёнки вида «AI» (`OnViewSettingsMenuBuild`).
* `lib/main/` — страницы (`AdminPage`, `PublicPage`), таблицы, обслуживание, опция тестовых пользователей.
* `public/` — публичная страница, ajax, `art.php`; `admin/list.php` — страница списка; `install/layout.php` — раскладка для портала из git.
* `tests/` — тесты на заглушках, запуск `./build.sh --check`.

## Линейка ИИ: зависимости и связь событиями

shef.toolsai разделён на четыре модуля. Зачем: баннеры, база знаний
и чат ставятся по желанию и выпускаются отдельно, а основной модуль от них
не зависит. Связь — только событиями D7 (`Bitrix\Main\Event`).

Версии — последние релизы в GitHub на 2026-10-30; что стоит на портале stuttgart, знает владелец.

| модуль | репозиторий | версия | обязательно нужен | по желанию |
|---|---|---|---|---|
| `shef.toolsai` | [bx-shef/toolsai](https://github.com/bx-shef/toolsai) | 1.76.0 | `shef.options`, `shef.problems`; модули ядра `ai`, `crm` — проверка в установщике | — |
| `shef.toolsaiassistant` | [bx-shef/toolsai-assistant](https://github.com/bx-shef/toolsai-assistant) | 1.72.0 | `shef.options`, `shef.problems`, `shef.toolsai` (модель, квота, журнал расхода, реестр промптов, история записи) | `shef.toolsaikb` — поиск статей для ответа |
| `shef.toolsaicrm` | [bx-shef/toolsai-crm](https://github.com/bx-shef/toolsai-crm) | 1.15.5 | `shef.options`, `shef.problems` | — |
| `shef.toolsaikb` | [bx-shef/toolsai-kb](https://github.com/bx-shef/toolsai-kb) | 1.11.0 | `shef.options`, `shef.problems`; модуль ядра `note` 26.250.0+ — проверка в установщике | — |

| событие | кто шлёт | кто отвечает | что передаёт |
|---|---|---|---|
| `shef.toolsai:OnPromptRegistryBuild` | toolsai | assistant | роли чата в реестр промптов |
| `shef.toolsai:OnPromptChanged` | toolsai | — (для своих модулей) | код изменённого промпта |
| `shef.toolsai:OnPromptPlacesCollect` | toolsai | — (для своих модулей) | места «Где доступен» промпта |
| `shef.toolsai:OnViewRowActionsBuild` | toolsai | assistant | пункт строки в виде «AI» |
| `shef.toolsai:OnViewToolbarBuild` | toolsai | assistant | кнопка в шапке вида «AI» |
| `shef.toolsai:OnViewSettingsMenuBuild` | toolsai | assistant, announce, kb | пункты шестерёнки вида «AI» |
| `shef.toolsaicrm:OnAnnouncementsCollect` | announce | toolsai | объявления по умолчанию |
| `shef.toolsaicrm:OnAnnouncementPlacesCollect` | announce | — (для своих модулей) | места показа объявлений |
| `shef.toolsaikb:OnKbSourcesCollect` | kb | toolsai | пакет статей справки (`shef.toolsai:guide`) |
| `shef.toolsaiassistant:OnChatPlacesCollect` | assistant | toolsai | места «Где показывать чат» |

## Открытые вопросы

* Отделы в аудитории — без подотделов. Нужны ли подотделы?
* `shef.toolsai` может сам отдавать свои места событием
  `OnAnnouncementPlacesCollect` — тогда строку вида «AI» (`PlaceCollector::TOOLSAI_VIEW`)
  можно убрать.
* Удаление объявления модуля — только выключение своей копией.
* «Сохранить» в форме читает объявление до блокировки (для даты публикации и
  картинки) и пишет форму целиком: одновременная правка из MCP проигрывает
  форме. Нужна ли защита (версия объявления)?
* Поиск объявления и право модуля повторены в REST и контроллере — общий
  класс?
